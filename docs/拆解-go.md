# 拆解：围棋

只看公开资料：中国围棋协会《中国围棋竞赛规则》的公开转述（新浪体育、萌娘百科「围棋」词条、CMU 的英文译本 The Chinese Rules of Go）、
日本规则英译本（CMU）、John Tromp 的 Tromp-Taylor 规则原文、GTP 第二版草案（GNU Go 作者 Gunnar Farnebäck 的邮件列表与 PDF）、
维基百科 Benson's algorithm 词条与 GNU Go `unconditional.c`、OGS 论坛里关于点目和自动判死活（autoscore，用 KataGo 归属估计）的讨论、
Michi / Pachi 一类开源 MCTS 程序的公开思路。野狐、弈城、OGS、KGS 只学交互习惯（点交叉点落子、悬停预览、虚手键、终局标地盘和死子），不照搬外观。

## 一、规则要点

| 项目 | 主流做法 | 我们 |
|---|---|---|
| 棋盘 | 正式比赛 19 路；入门和快棋常用 9 路、13 路 | `setup.size` 选 9 / 13 / 19，**默认 9 路**（每步一次模型调用，19 路一盘两三百手太贵太慢） |
| 计分 | 中国规则数子法（子 + 空）；日韩数目法（空 + 提子）；Tromp-Taylor 数子（子 + 只挨着一方的空点） | **数子法**，数法按 Tromp-Taylor：提掉死子后，子 + 只挨着一方的空点；挨着双方的空点（单官）谁都不算 |
| 贴目 | 中国规则黑贴 3¾ 子（= 7.5 目）；日韩 6.5 目 | `setup.komi`，默认 7.5（数子法下等价 3¾ 子），可改；半目贴目没有和棋 |
| 自杀 | 中日韩都禁止；Tromp-Taylor 允许 | **禁止**（回答里写自杀点会被退回并说明原因） |
| 打劫 | 中国规则：全局同形禁止；日本规则：只禁立即提回，三劫循环等判无胜负 | **全局同形禁着**（positional superko）：落子后的全盘局面不能和以前任何局面相同（不看轮到谁）；局面用 Zobrist 哈希记在 state 里 |
| 虚手 | 可以虚手；双方连续虚手进入终局 | 同；行动 id `pass` |
| 终局 | 双方连续虚手后，双方确认死活再数子；有争议时继续下或由裁判判 | 双方连续虚手，或下到 `size² × 3` 手，**系统确定性地判死子**后数子（见第三节）；没有确认 / 争议环节 |
| 认输 | 随时可以认输 | 模型写「落子：认输」（行动 `resign`）；真人用对局页状态栏现成的认输键（框架的判负机制），画面上不再放一个 |
| 让子 | 让子棋放座子，贴目改为 0 或半目 | 不做（只有分先） |
| 计时 | 读秒、包干、费舍尔 | 用框架的两人棋类每步限时（`features.clock`，默认 5 分钟，累计超时 3 次判负）；真人超时由系统用初级内置 AI 代走一步：不填自己的眼、不把自己的一串子送进虎口，对方刚虚手且按正式终局判定自己能赢时跟着虚手（不会替真人平白虚手） |
| 坐标 | GTP：列 A–T 跳过 I，行号自下而上 1–19（例如 D4、Q16）；SGF 用小写字母对 | **GTP 写法**，行动 id 用大写（`D4`），虚手 `pass`、认输 `resign` |

为什么跳过 I：GTP 草案作者解释是 I 容易和 J、l 看混，这个习惯在纸面棋谱时代就有，GTP 沿用了人的写法。提示词里专门提醒「H 的右边是 J」。

## 二、流程

1. 开局：空盘，黑先。`create` 不用随机数（围棋没有发牌），同样的记录永远重放出同一局面。
2. 每一手：落子（提掉没气的对方棋串；自己没气又提不到子是自杀，禁止；结果局面出现过则是同形，禁止），或虚手。
3. 对方虚手后轮到你：提示词里写明「你也虚手，对局立即结束并数子」。
4. 双方连续虚手、或手数到上限：当场判死子并数子，结果写进 state（`state.final`），之后 `outcome`、`view` 只读它，不再重算。
5. 认输：对方胜，不数子。
6. `rankedSeries: { legs: 2 }`：排位赛交换先后手各下一盘（和黑白棋一样）。

结果文字示例：「双方连续虚手，终局数子（判 黑死子 2 颗）：黑 45，白 36 + 贴目 7.5，黑胜 1.5 目」；视图里另给短的一句 `final.result`（「黑胜 1.5 目」）。
「胜 N 目」是双方数子总数（白方加上贴目）之差。中国规则的正式说法要再除以 2（以一方过半数为界，差 1.5 记作「胜 ¾ 子」），
但贴目是按目说的（7.5 目），差距也按目说，观众不用换算，也和 OGS / KGS 的「B+1.5」一致；原先写的「胜 1.5 子」和正式的「¾ 子」对不上，容易误会。

## 三、终局判定与死活处理

成熟产品的做法：
- 人对人（野狐、弈城、KGS、OGS）：终局后进入「点死子」阶段，双方点选死子、确认，有分歧就继续下。
- OGS 的自动判（autoscore）：用 KataGo 的归属估计（每个点归谁的概率）标死活，黑先、白先各估一次；论坛上仍有大块死棋被判活、孤子一半概率被判活的反馈。
- 程序对局（GTP / CGOS）：一般要求下到「把死子都提干净」再虚手，按 Tromp-Taylor 直接数，不需要判死活。

我们的情况：大模型、随机选手常常不提死子就虚手，也没有人来确认；结果要**完全确定**（同样的记录在服务器和浏览器重放出同一个结果），所以选了「Benson + 带种子的随机对局 + 一条势力规则」：

1. **Benson 无条件活棋**：对方连下多少手都提不掉的棋串（至少两个「要害区域」），一律算活，不参与下面的判断。
2. **随机对局估计归属**（蒙特卡洛）：从终局局面出发跑固定局数的随机对局（9 路 1600 局、13 路 800 局、19 路 400 局，约 0.1–0.2 秒；黑先、白先各一半，避开 OGS 说的「谁先走结论不同」）。
   随机对局不填自己的眼、会提打吃的子、会逃被打吃的子；没有别处可下时只肯送吃三颗以内的子，更大的一串宁可虚手
   （原来是「没别处下就送」，双活的棋会自己填掉公气被提，整块被判死——挑刺时修的）。一串子平均有 ≥ 70% 的情况归对方（平均归属 ≤ −0.4），判死：被围住、只有一只眼、气紧的棋。
3. **对方地里的孤子、残子**：随机对局把大块的空当成双方都能下的地方，看不出「对方空里的一颗孤子」是死的。
   所以再看这串子所在的势力区（自己的子 + 空点连成、被对方子围住的一片）：挨着这片空点的对方子数 ≥ 自己子数的 2 倍，且随机对局也不看好它（平均归属 < 0.25），判死。
4. 提掉死子，按 Tromp-Taylor 数子。

确定性：随机数是自带的 mulberry32，种子取自局面的 Zobrist 哈希 + 路数，全程只有整数运算和固定次数的循环，Node 和浏览器结果相同；测试里同一局面算两次结果完全相等。

局限（写给观众看的结果可能和高手判断不同）：
- 实测判对的：角上无眼的残子、对方地里的孤子、只有一只眼的棋、直二（死）；直四、曲四、分开的两只眼、双活（各一眼共一气、无眼两公气）（活）。测试里都有。
- 随机对局不会读棋：**方四（2×2 的眼，实际是死棋）会判活**；直三、刀把五、板六这类「谁先下谁说了算」的棋和没下完的对杀一律按活棋留在盘上（双方都虚手了，谁也没去动它）；劫活按当时盘面算。
- 四颗子以上的小双活之外，三颗以内互相咬住的小双活仍可能被判死（随机对局会送吃三颗以内的子）。
- 判定用的局数加倍后，同一局面换种子结果基本不变（48 个中盘 / 终局局面里 3 个的死子集合会变，都是没下完的中盘）。
- 第 3 条是经验规则：对方势力里人数很少的一小块棋，即使其实能做活（空间够大、对方不应），也会判死；这正是人类「对方会应，所以是死棋」的习惯判断。
- 没有确认和争议环节。对模型局来说这是可以接受的简化：模型要想自己的棋不被误判，最好像程序对局那样把死子提干净再虚手（提示词里写明了「系统判定死子后数子」）。

## 四、给模型的提示词

- 系统提示词：规则（数子法、贴目、提子、禁止自杀、全局同形、虚手终局、手数上限、可以认输）、坐标（特别写「跳过字母 I，H 的右边是 J」）、五行输出格式：
  `判断 / 威胁 / 理由 / 胜率：NN% / 落子：D4`（停一手写「落子：虚手」，认输写「落子：认输」），除落子外不超过 80 字。
- **什么时候虚手**写进了系统提示词：边界封好、没有能提的子、没有要补的棋才虚手；数子法在自己地里落子不亏，对方留在自己地里的残子拿不准就提干净（免得被系统判活）；不要往对方的铁空里送子、不要填自己的眼；对方虚手后没棋可下且不落后就也虚手。
- 每一手的提示：第几手 / 上限（剩 20 手以内提醒「只剩 N 手就强制终局」）、上一手（含提了哪些子；对方虚手时提醒「你也虚手就终局」）、盘上子数、双方提子数、**禁着点**（打劫的同形点、自杀点，带原因）。
- **气紧的棋串**：把双方只剩 1 气（写明气在哪）、2 气的棋串直接列出来。大模型数气比数格子还差，这是盘面上的事实，不是替它出主意。
- 盘面过半或对方虚手后，附上「按现在的盘面直接数」的黑白点数（不判死活），帮它判断该不该收兵。
- 棋盘文字：**每格一个字符、用空格隔开**（X 黑、O 白、. 空），**行首行尾都写行号、上下都写列字母**。大模型数格子很差，两头都有标尺，对齐着看不容易数错；没有用星位符号，免得和棋子混淆。
- 开了「列出合法着点」（框架的 showLegal）时附上全部可下的点。
- 解析很宽松：大小写、全角（Ｄ４）、中文数字（c三、Q十六）、「d 4」「D-4」、写反的「4D」、「天元」、markdown 加粗 / 代码 / 标题记号（`**落子**：D4`）、「落子位置：」；「虚手 / 停一手 / pass」「认输 / resign」。
  「落子：」写了几行取最后一行；一行里有几样（「D4（不能虚手）」「虚手（D4 没价值了）」「不认输，下 C3」）取写在最前面的那样；没有「落子：」行时取全文最后一个坐标或单独一行的「虚手」。
  不合法时给出具体原因：已经有子、自杀、全局同形（提示去找劫材）、没有 I 列、超出棋盘（附上正确范围）、只有数字缺列字母（「４四」「4-4」）、不是坐标。

## 五、内置 AI 与局面评估

浏览器里也要能跑，所以不用任何 Node 模块，自写快速棋盘（带边界的一维数组 + 棋串循环链表 + 伪气数，单线程每秒 9 路约 1.3 万局随机对局、19 路约 2700 局）。

| 等级 | 做法 | 每步耗时 |
|---|---|---|
| 1 | 随机合法着点，不填自己的眼、不送吃自己的一串子；对方虚手且按终局判定自己能赢时跟着虚手 | < 1 ms（跟着虚手那一步约 0.1 秒） |
| 2 | UCT 蒙特卡洛树搜索：先验（提子、逃子加分，送吃、开局下一线减分）+ 随机对局里提子、逃子 | 9 / 13 / 19 路 350 / 450 / 550 ms |
| 3 | 再加 RAVE（AMAF）、随机对局里应上一手附近的局部、更多时间 | 900 / 1000 / 1100 ms |

实测（本机单线程，交换先后手）：9 路等级 2 对等级 1 6:0（另以每步 1500 局的定量版 12:0），等级 3 对等级 2 12:0；13 路等级 3 对等级 2 2:0；19 路 1:0（448 手）。

- 根上「能提的子、能逃的子」再加一大笔先验：随机对局分辨不出一两颗子的得失，不加的话常放着能提的子不提。
- 什么时候虚手（等级 2、3）：对方刚虚手、现在终局（按第三节判死子）自己能赢；或者所有能下的点在搜索里的归属都已经定了（|平均归属| ≥ 0.9，继续下只是填自己的地或往对方地里送子）。
- 评估 `evalSpec`：`engine: 'local'`，用等级 3 的配置搜 200 ms，返回走棋方期望得分和最多访问的着点（或 `pass`），种子取自局面哈希。
  期望得分 = 一半「这次搜索里随机对局的胜局比例」+ 一半「平均盘面差折成 0–1（logistic，尺度 = 路数 × ⅔）」。
  原来用「最好那一手的胜率」（还掺着先验的虚拟胜局），步与步之间跳得厉害：9 路上让等级 3 自己连下三盘，不是引擎首选的 93 手里有 41 手被标成缓着 / 失误 / 大漏着；
  改后同样的棋只有 1 手被标。代价是偏保守：插进去的随机着从 18/46 被标降到 10/46——只标得出明显的坏棋（送吃、漏提、往死地里填），细微的缓着标不出来。

## 六、画面要点

- 榧木棋盘（木纹、漆框、厚度）和五子棋同一套质感；9 / 13 / 19 路共用一个画面尺寸，按路数算格距；星位、**四边坐标**（列字母跳过 I）。
- 黑子哑光石、白子贝壳瓷光，带投影和高光；最后一手一个小红点；落子轻落。
- 提子：被提的子在原处淡出（约半秒），不是直接消失，观众看得出发生了提子。
- 打劫点：视图里有 `ko`（现在不能立即提回的点，没有就是空数组），观众和回放也看得到，不只是轮到的真人。
- 顶上漆框：左黑右白的提子数；对方虚手时中间写「白方虚手」；真人行动时中间是「虚手」键（认输在对局页状态栏，不重复）。
- **虚手要点两下确认**：第一下按钮变红、写「确认虚手」，4 秒后或点了棋盘就复原；对方刚虚手时写的是「确认终局」（再按一下对局就结束数子）。
- **手数开关**：棋盘上方可以开关每颗子上的手数（记在 localStorage 里），最后一手的手数是红色。
- 终局：每个点画归属小方块（黑方块 / 白方块）；死子画成半透明加一个叉，下面不再画归属方块；顶栏改成双方点数（白方写「45+7.5」）和胜负。
- 真人落子：鼠标悬停显示半透明预览子，只在合法点（来自 `actions`，自杀点、同形禁着点不响应）；手机上点一下放预览子，再点顶栏的确认键或再点同一个点才落下。
- 复盘时引擎的最好着点画一个红色虚线圈。

## 七、简化与原因

- **没有点死子 / 确认阶段**：对局里多是模型和程序，没有人能确认；用确定性的自动判定，局限写在第三节。
- **全局同形只按局面判**（positional，不看轮到谁）：最简单，和 Tromp-Taylor、中国规则精神一致；三劫循环之类自然被禁止，不需要「无胜负」。
- **手数上限 size² × 3**：防止模型来回填子、反复打劫拖死对局；正常对局远到不了。
- **单官不算**：中国规则正式比赛要求单官下完；模型常常不收单官，按 Tromp-Taylor 挨着双方的空点谁都不算，不影响结果的公平性（双方都可以去下）。
- **不做让子、不做日韩规则**：分先 + 数子法最容易对模型说清楚，也不用处理「提子数」「填子」等数目法细节。实力悬殊时可以用 `setup.komi` 调贴目（−50 到 50）代替让子。
- **没有「和棋」「无胜负」**：贴目是整数且正好打平时名次并列；三劫循环被全局同形挡住，不会无胜负。
- **内置 AI 不认输**：蒙特卡洛的胜率噪声大，自动认输容易误判；输了就下完数子。

## 八、需要框架配合的地方

- 注册：`games/index.js` 的 GAMES 加 `go`，`web/stage/index.js` 的 LOADERS 加 `go: () => import('./go.js')`。
- 开局表单：`setup.size`（9 / 13 / 19）、`setup.komi`（默认 7.5）现在没有界面入口，需要的话在开局页加两个选项；不传就是 9 路 7.5 目。
- 对局页着法表的阵营小棋子颜色（`SIDE_DOT`）可以给 `go` 加上和五子棋一样的黑白。
